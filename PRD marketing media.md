# PRD: «Маркетинг Медиа»

**Версия:** 0.1 (черновик по итогам обсуждения)
**Автор:** Dulat Zhumagazin, начальник отдела маркетинга и PR-продвижения, Агентство «Хабар»
**Тип документа:** Product Requirements Document
**Статус:** Draft — приложение уже собрано как рабочий прототип (веб-артефакт), документ фиксирует его логику для дальнейшего развития/передачи в разработку

---

## 1. Проблема и контекст

Пользователь — медиа-маркетолог/PR-специалист, изучающий вайб-кодинг, столкнулся с двумя конкретными болями:

1. **Промоплан приходится каждый раз собирать с нуля** — для сериалов, телепрограмм, фильмов, документальных проектов и медиа-брендов нет быстрого способа получить черновик плана продвижения (посыл, контент для коротких видео, график, метрики).
2. **Сравнительный анализ конкурентов делается неправильно/неудобно.** Пользователь знает, что в англоязычном пространстве есть сервисы (пример — trendsee.io), которые по индустрии/продукту показывают, что делают аналогичные конкуренты в соцсетях, какие у них тренды и форматы — но у себя (KZ/СНГ, медиа-вертикаль) такого удобного инструмента под рукой нет, а вручную сравнивать корректно (по тем же каналам/метрикам) не получается.

**Уточнение приоритета от пользователя (ключевое):**
> «В первую очередь это сравнительный анализ — показать, что делают конкуренты в части маркетинга и промо и соцсетей, тренды на данный момент (условно как trendsee.io) плюс полный сравнительный анализ. Потом маркетолог делает анализ контента, анализ продукта, анализ соцсетей, анализ тренда — и после этого делает промоплан.»

Отсюда следует порядок ценности продукта:

**Анализ конкурентов (продукт → контент → соцсети → тренды → итог) → Промоплан**, а не наоборот.

## 2. Целевые пользователи

- Маркетологи и PR-специалисты медиакомпаний (пресс-служб нет — задачи ложатся на маркетинг).
- Продюсеры сериалов/фильмов/документальных проектов.
- SMM-специалисты, отвечающие за продвижение теле- и медиапроектов.
- Контекст пользователя: Агентство «Хабар» (Казахстан), продвижение документальных проектов, сериалов («Таксист — Байып кет»), работа с блогерами, антикризисные коммуникации. Нужны тексты и планы на русском и казахском языках.

---

## 3. Цели продукта

1. Дать маркетологу структурированный, отчуждаемый (копируется/скачивается) **сравнительный анализ конкурентов** по четырём срезам: продукт, контент, соцсети, тренды — без необходимости вручную сводить данные из разных сервисов в таблицу.
2. На основе этого анализа (или отдельно, без него) — сгенерировать **черновик промоплана на одну страницу**: посыл, идеи Reels/Shorts, график до/после запуска, метрики.
3. Дать пользователю понимание **где брать реальные данные** о конкурентах (аналитика соцсетей, реклама, тренды, мониторинг упоминаний), поскольку сам инструмент не имеет доступа в интернет.
4. Работать полностью на двух языках интерфейса вывода — русский и казахский.

### Не цели (out of scope v0)
- Автоматический сбор данных о конкурентах из интернета/API соцсетей (нет живого доступа к данным, как у Popsters/Fanpage Karma/trendsee.io).
- Публикация/шедулинг контента.
- Многопользовательская совместная работа в реальном времени (кроме локального сохранения в браузере).
- Точные прогнозные цифры без ввода пользователя (система намеренно избегает «выдуманных» показателей).

## 4. Ключевое ограничение архитектуры

Приложение — self-contained веб-страница (Claude Artifact), выполняющая роль:
- калькулятора/конструктора форм (без бэкенда, хранение в `localStorage` браузера, per-viewer, не расшаривается между пользователями);
- клиента к Claude через встроенную возможность «спросить Claude» (`sample`) — каждый вызов независим, без памяти, без доступа в интернет и без реальных «живых» данных о конкурентах.

**Следствие для продукта:** всё, что похоже на «живые данные, как в trendsee.io» (актуальные тренды, реальная статистика чужих аккаунтов), в MVP — это либо:
(a) данные, которые вносит сам пользователь вручную (цифры по соцсетям, наблюдения за контентом конкурентов), либо
(b) гипотезы Claude на основе общих знаний о рынке — явно помечаются как гипотезы и требуют проверки пользователем через внешние источники.

Приложение явно направляет пользователя во внешние специализированные сервисы для получения актуальных цифр (раздел «Источники данных»).

## 5. Структура продукта (Information Architecture)

Три вкладки верхнего уровня, в порядке приоритета:

### 5.1 «Анализ конкурентов» (главная вкладка, открывается по умолчанию)

Общий блок сверху: **Список конкурентов (реестр)** — общий для срезов «Продукт», «Контент», «Тренды»:
- Название, заметка/УТП, ссылка.
- До 10 конкурентов, добавление/удаление, хранится в `localStorage`.

Пять под-вкладок (в порядке, названном пользователем: контент → продукт → соцсети → тренды → итог):

**a) Контент**
- Для каждого конкурента из реестра — текстовое поле «наблюдения»: что и как публикует (рубрики, тон, форматы, примеры), заполняется пользователем вручную.
- Кнопка «Разобрать контент с Claude» — по сырым наблюдениям формирует структурированный разбор: темы/рубрики, тон и формат подачи, паттерн частоты публикаций, «чего не хватает» (белое пятно/идея для отстройки).
- Явное ограничение: Claude не придумывает факты о контенте, которых нет в наблюдениях пользователя.

**b) Продукт**
- Таблица: строки — «Мой проект» (данные подтягиваются из карточки промоплана) + конкуренты из реестра; столбцы — Позиционирование, УТП, Формат/продукт, Аудитория, Слабое место.
- Ячейки редактируются вручную.
- Кнопка «Заполнить пробелы с Claude» — заполняет только пустые ячейки (гипотезы по названию/заметке о конкуренте), не трогает заполненные пользователем. Явно помечается как гипотеза, а не факт.

**c) Соцсети** (числовой сравнительный анализ — наиболее проработанный модуль)
- Отдельная таблица на каждую площадку: Instagram, TikTok, YouTube, Telegram, Facebook.
- Столбцы: аккаунт, подписчики, постов/неделю, ср. просмотры, ср. лайки, ср. комментарии, ср. репосты+сохранения, форматы.
- Автоматический расчёт на лету:
  - **ER** = (лайки + комментарии + репосты) ÷ подписчики × 100
  - **Охват/подписчики** = просмотры ÷ подписчики (показывает, «раздаёт» ли площадка контент за пределы базы)
- Первая строка таблицы всегда — «Мой проект» (выделена цветом).
- Блок «Сравнение по метрикам»: по каждой метрике (ER, охват/подписчики, частота публикаций, реакций в неделю) — бар-чарт конкурентов, медиана конкурентов (пунктир), вердикт «мой проект выше/ниже медианы на N%».
- Экспорт в CSV, предзаполненный пример на вымышленных данных, кнопка «Очистить площадку».

**d) Тренды** (аналог логики trendsee.io в рамках доступных возможностей)
- Ручное добавление: название тренда, описание, ссылка на источник.
- Кнопка «Предложить тренды с Claude» — 5 гипотез форматов/трендов под конкретный проект и площадки, с явной пометкой «гипотеза без доступа к live-данным, проверяйте через источники».
- Карточки трендов визуально различают «добавлено вручную» / «гипотеза Claude».

**e) Итог**
- Кнопка «Собрать сравнительный анализ» — сводит данные всех предыдущих срезов (продукт + контент + соцсети + тренды) в один связный отчёт от Claude: общий вывод, сравнение по продукту, по контенту, по соцсетям, тренды к использованию, незанятые ниши, 5 рекомендаций для промоплана.
- Кнопка «Использовать в промоплане» — передаёт этот отчёт как контекст в генератор промоплана и переключает пользователя на вкладку «Промоплан».

### 5.2 «Промоплан»
- Форма карточки проекта: тип (сериал/телепрограмма/фильм/документальный проект/медиа-бренд/подкаст), название, описание, аудитория, дата запуска, доступные площадки (чипсы), главная задача (просмотры/охват/подписчики/вовлечение/трафик/репутация) + уточнение, бюджет (нет/небольшой/средний/крупный).
- Опциональный чекбокс **«Учитывать сравнительный анализ конкурентов»** (появляется, если итоговый анализ уже собран на вкладке «Анализ конкурентов»).
- Два способа получить план:
  1. **«Собрать план с Claude»** — полноценная генерация: посыл, слоган, позиционирование, контент-рубрики, 6 идей для Reels/Shorts (с хуком на первые 3 секунды и привязкой к площадке и таймкоду T±N дней), график из 5–6 этапов от T-30 до T+30 с конкретными действиями, 5–7 метрик с ориентирами, риски, чек-лист «начать на этой неделе».
  2. **«Быстрый шаблон»** — мгновенная генерация без AI (детерминированный шаблон на основе введённых данных: тип проекта, площадки, бюджет, задача) — работает офлайн/без разрешения на Claude.
- Вывод оформлен как документ на одну страницу с датами, обратным отсчётом до запуска (T-N), карточками Reels, построчным рундауном этапов, таблицей метрик.
- Копирование текста, скачивание `.md`, поддержка двух языков вывода (RU/KK).

### 5.3 «Источники данных»
- Методичка «сравнительный анализ за один вечер» (5 шагов).
- Каталог внешних инструментов по трём категориям:
  - Аналитика аккаунтов конкурентов (Popsters, LiveDune, TGStat, Social Blade, Rival IQ, Fanpage Karma, Similarweb).
  - Тренды и вдохновение — аналог trendsee.io (trendsee.io, TikTok Creative Center, Exploding Topics, Google Trends, Pinterest Trends).
  - Реклама конкурентов и мониторинг упоминаний (Meta Ad Library, YouScan, Brand Analytics).

## 6. Пользовательский флоу (основной сценарий)

1. Маркетолог открывает приложение → попадает на вкладку «Анализ конкурентов».
2. Вносит 3–5 конкурентов в общий реестр.
3. Проходит по под-вкладкам: описывает наблюдения по контенту → заполняет таблицу продукта → вносит цифры соцсетей по нужным площадкам → фиксирует тренды.
4. На каждом шаге может попросить Claude дозаполнить пробелы/структурировать/предложить гипотезы.
5. Нажимает «Собрать сравнительный анализ» → получает единый отчёт.
6. Нажимает «Использовать в промоплане» → переходит на вкладку «Промоплан» с уже включённым чекбоксом «учитывать анализ».
7. Заполняет карточку проекта (если ещё не заполнена) → «Собрать план с Claude».
8. Получает промоплан, копирует/скачивает.
9. При необходимости уточнить цифры — идёт во вкладку «Источники данных» за реальными сервисами аналитики.

## 8. Нефункциональные требования

- **Прозрачность источника данных**: каждый вывод помечен — «пример», «шаблон без AI», «собрано Claude», «добавлено вручную» — пользователь всегда понимает, откуда цифра/утверждение.
- **Честность AI-гипотез**: любой AI-вывод о конкурентах без входных данных пользователя явно маркируется как предположение, а не факт, с рекомендацией проверить через реальные сервисы.
- **Отзывчивость**: интерфейс работает на ширине от ~400px (мобильный) до десктопа.
- **Двуязычность**: переключатель RU/KK влияет на язык генерируемого текста (не на интерфейс кнопок).
- **Устойчивость к отказу AI**: если доступ к AI не выдан/недоступен — приложение не ломается, доступны шаблон и ручные таблицы.

## 9. Модель данных (клиентская, localStorage)

- `form` — карточка проекта для промоплана.
- `reg` — реестр конкурентов `[{id, name, note, link}]`.
- `product` — `{competitorId: {positioning, usp, format, audience, weak}}`.
- `content` — `{competitorId: {notes, ai: {themes, tone, frequency, whitespace}}}`.
- `mx` — матрица соцсетей `{platform: [{name, followers, ppw, views, likes, comments, shares, fmt}]}`.
- `trends` — `[{id, title, desc, link, source: "user"|"ai"}]`.
- `analysisSummary` — текст консолидированного отчёта.
- `lang` — язык вывода (`ru`/`kk`).

Все данные — per-browser, не синхронизируются между устройствами/пользователями в MVP.

## 10. Метрики успеха продукта (для самого инструмента)

- Время от открытия приложения до готового промоплана (цель: < 15 минут для рутинного проекта).
- Доля пользователей, доходящих до вкладки «Итог» перед генерацией промоплана (показывает, действительно ли анализ используется как основа).
- Количество ручных правок в сгенерированном плане (косвенный показатель качества черновика).
- Обращения в раздел «Источники данных» — показывает, что инструмент осознанно используется как отправная точка, а не как замена реальной аналитики.

## 11. Риски и ограничения

| Риск | Митигация |
|---|---|
| Пользователь примет AI-гипотезы о конкурентах за факты | Явная маркировка «гипотеза/пример», рекомендации проверять через внешние сервисы |
| Нет доступа к реальным live-данным (в отличие от trendsee.io и подобных) | Раздел «Источники данных» с прямыми ссылками на специализированные сервисы; чёткое позиционирование инструмента как «конструктор анализа», а не «сборщик данных» |
| Данные не сохраняются между устройствами/пользователями | Заложить в будущих версиях серверное хранилище (например, `db`-капабилити) для командной работы |
| Сравнение площадок с разной механикой охвата (например, Instagram vs Telegram) даёт искажённую картину | Матрица соцсетей разделена по площадкам — сравнение только внутри одной площадки |

## 12. Дальнейшее развитие (не в MVP)

- Общая (командная) база данных вместо localStorage — чтобы несколько маркетологов агентства работали с одним реестром конкурентов.
- Интеграция с внешними API аналитики соцсетей (при наличии доступа/бюджета) вместо ручного ввода цифр.
- Библиотека промоплана по прошлым проектам агентства (бенчмарк своих же кампаний).
- Экспорт итогового анализа и промоплана в единый PDF/презентацию.
- Уведомления/напоминания по этапам графика (T-7, T0, T+7 и т.д.).

## Приложение: история решения (из переписки)

1. Первый запрос: веб-приложение для маркетологов/PR/продюсеров — форма проекта → промоплан на одну страницу + сравнительный анализ конкурентов как отдельная боль пользователя.
2. Собран первый прототип: вкладки «Промоплан», «Конкуренты» (числовая матрица соцсетей), «Где брать данные».
3. Уточнение пользователя: сравнительный анализ — это главное, и он должен быть **полным**: не только соцсети, а продукт + контент + соцсети + тренды (аналог trendsee.io), и только после этого — промоплан.
4. Прототип переработан: вкладка «Анализ конкурентов» стала первой и главной, добавлены срезы «Продукт», «Контент», «Тренды», «Итог»; промоплан теперь может учитывать итоговый анализ.
5. Рабочий файл прототипа: `promoplan.html` (Claude Artifact, использует капабилити `sample` для AI-генерации и `downloads` для сохранения файлов).
